## 1. 项目概览

CQU321 是重庆大学校园服务小程序，基于 uni-app 框架实现**一套代码编译到 iOS、Android、H5 和微信小程序**等多个平台。

核心功能模块：

| 模块 | 页面路径 | 功能描述 |
|------|----------|----------|
| 首页 | `pages/index/index` | 课程提醒卡片、活动轮播、功能入口导航 |
| 成绩查询 | `pages/grade/index` | 学期成绩展示、GPA 计算、成绩单 |
| 课程表 | `pages/curriculum/index` | 周课表视图、自定义课程、课表设置 |
| 查课 | `pages/course_info/index` | 课程检索、课程详情与评分 |
| 考试安排 | `pages/exam/index` | 考试日程、手动添加考试 |
| 图书馆 | `pages/library/index` | 借阅记录查询 |
| 空教室 | `pages/empty_room/index` | （暂未实现） |
| 常用信息 | `pages/general_info/index` | 校历、校车等常用信息 |
| 生活 | `pages/life/index` | 一卡通、水电费查询 |

后端 API 基地址：`https://api.321cqu.com/v1`

### 依赖方向（重要）

```
Pages → Composables / Models → Core
  │         │
  └─────────┤
      Domain / Utils
```

- **Pages** 只能导入 Composables、Models、Utils
- **Models** 可以导入 Core、Utils、Domain
- **Core** 不依赖 Pages 或 Models（最底层）
- **Domain** 是纯函数层，不应有副作用或 UI 依赖
- **Composables** 封装响应式逻辑，被 Pages 使用

## 6. 核心设计模式

### 6.1 Model 单例模式

所有数据模型继承 `StdModel`，使用 `getInstance()` 获取单例：

```typescript
import CourseModel from "@/models/CourseModel";

const courseModel = CourseModel.getInstance();
await courseModel.update(termOffset);
const data = await courseModel.getCoursesData(TermOffset.CurrTerm);
```

每个 Model 内部封装：
- **API 调用**：通过 `stdRequest` 从后端拉取数据
- **本地缓存**：通过 `stdSetStorage` / `stdGetStorage` 持久化到本地
- **内存缓存**：通过实例属性 `_xxx` 避免重复读取

Model 基类 `StdModel` 提供 `clearAll()` 统一清理所有模型缓存。

### 6.2 页面数据加载模式

大多数需要登录的页面使用 `useAuthorizedPageData` 统一管理状态：

```typescript
const { pageState, loadPageData, refreshPageData } = useAuthorizedPageData({
  hasReadyData: () => items.value.length > 0,
  loadData: async () => { /* 从 Model 加载数据 */ },
  refreshData: async () => { /* 从服务器刷新数据 */ },
  logTag: "GradePage"
});
```

状态流转：`loading` → `unauthorized` / `empty` / `error` / `ready`

配合 `PageState` 组件渲染对应的 UI 状态。

### 6.3 PageShell + NavigationBar

每个页面使用 `PageShell` 包裹内容，自动处理导航栏和布局：

```vue
<template>
  <PageShell>
    <!-- 页面内容 -->
  </PageShell>
</template>
```

`NavigationBar` 在 `pages.json` 中配置 `navigationStyle: "custom"` 后作为自定义导航栏使用。

## 7. 页面开发流程

### 新增页面步骤

1. 在 `src/pages.json` 中注册页面路径

## 8. 认证与网络请求

### 认证流程

```
登录页面 → getUserToken(用户名, 密码) → 获取 Token + RefreshToken
         → validateAuth → 获取用户信息 → 存储到本地
```

- **访问令牌 (Token)**：内存中，用于 API 请求的 Authorization Header
- **刷新令牌 (RefreshToken)**：本地存储，用于自动续期
- **密码**：base64 混淆后存储于本地，作为 refresh token 过期后的最终恢复手段

### 发送请求

```typescript
import { stdRequest } from "@/core/request";

// 需要认证的请求（默认）
const data = await stdRequest<ResponseType>({
  url: "/edu_admin_center/fetchScore",
  data: { sid: "20210001" }
});

// 不需要认证的请求
const data = await stdRequest<ResponseType>({
  url: "/public/someEndpoint",
  needToken: false
});

// 使用 App Token（首页活动等）
const data = await stdRequest<ResponseType>({
  url: "/important_info/homepages",
  tokenType: "app"
});
```

### 请求层架构

```
stdRequest (request.ts)
  → handleToken → 自动附加/刷新 Token
  → stdHttpRequest (httpClient.ts)
    → uni.request → 超时 15s、自动重试 1 次
    → StdNetworkError（401/403/5xx 分类处理）
```

## 10. 常见陷阱与注意事项

### 跨平台兼容

- **Flex 布局优先**：不要依赖 CSS Grid 或绝对定位做复杂布局，小程序兼容性差
- **uni-app API**：统一使用 `uni.xxx` 而非 `wx.xxx` 或 DOM API
- **`onLoad` 参数**：类型为 `Record<string, any> | undefined`，访问属性前做可选链检查
- **条件编译**：平台特定代码使用 `// #ifdef MP-WEIXIN` 等指令

### 样式

- 组件样式使用 `<style scoped>` 避免全局污染
- 全局样式修改编辑 `src/App.vue`、`src/App.css` 或 `src/uni.scss`
- 不要在 scoped 块内使用 `@import`（form.css 已全局导入）

### TypeScript

- **禁止** `as any` 绕过类型检查
- **禁止** 非空断言 `!` 未经运行时检查
- `catch (e)` 必须写 `catch (e: unknown)`
- API 响应必须定义精确接口类型，不要用 `any[]`

### 安全

- 密码本地存储使用 base64 混淆（`obfuscate` / `deobfuscate`），不可明文
- API 请求自动附加超时（15s）和重试（1 次）
- 存储清理使用 `stdClearAllStorage`，仅清应用自有键

### 旧代码

- `src/core/old.ts` 是遗留的旧版 API 客户端，指向 `zhulegend.com`
- 仅 `tutorial` 和 `about` 页面仍在使用，新功能不要引用它
- 待新 API 支持对应端点后移除
