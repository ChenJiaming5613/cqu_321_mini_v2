# 后续任务上下文

本文用于在新对话中快速恢复当前项目背景、已确认决策和后续执行计划。

## 项目背景

当前仓库是 UniApp + Vue 3 + TypeScript 微信小程序前端。入口为 `src/main.ts`、`src/App.vue`、`src/pages.json`。页面代码在 `src/pages/`，业务数据模型在 `src/models/`，网络、用户、Token、存储等基础能力在 `src/core/`，通用工具在 `src/utils/`。

目前完成度较高的页面是首页和成绩查询页。其余页面多为半成品或静态 UI，后续会根据设计稿逐步补全。

## 当前架构要点

主要依赖方向：

```text
pages -> models -> core/common -> core/network -> StdToken / StdUser / uni.request
pages -> pages/components
pages -> utils
models -> core/storage
models -> core/old
```

关键文件：

- `src/core/network.ts`：新 API 请求、登录、刷新 Token、绑定 OpenID。
- `src/core/old.ts`：旧 API 请求和旧资源 URL，目前后续应减少使用。
- `src/core/StdUser.ts`：用户信息单例和本地存储。
- `src/core/StdToken.ts`：Token 和 refreshToken 管理。
- `src/core/storage.ts`：`uni` 存储和文件下载封装。
- `src/models/ActivityModel.ts`：首页轮播，目前仍使用旧接口，需要优先迁移。
- `src/models/CustomCourseModel.ts`：自定义课程本地存储 + 旧云同步，云同步应暂时禁用或移除入口。
- `src/pages/index/about/index.vue`、`src/pages/index/tutorial/index.vue`：当前仍用旧接口拉 Markdown，后续改为静态 Markdown 链接。

## 执行计划

### 阶段 1：API 替换与功能裁剪

目标：先统一数据入口，减少旧接口依赖，避免后续页面重构时继续绑定旧后端。

建议顺序：

1. 迁移首页轮播 API。
   - 改 `ActivityModel`。
   - 新接口：`GET /important_info/homepages`。
   - 需要适配字段：`img_url`、`img_pos`、`jump_type`、`jump_param`。
2. 关于我们、教程改为静态 Markdown 链接。
   - 当前暂缓，后续对齐设计稿后再推进。
   - 改 `pages/index/about/index.vue`。
   - 改 `pages/index/tutorial/index.vue`。
   - 不再调用 `oldRequestV1`。
3. 禁用或移除自定义课程云同步入口。
   - `CustomCourseModel` 的本地增删保留。
   - `push()`、`pull()` 对旧接口的依赖暂不使用。
4. 清点并收敛 `oldRequestV1` 调用。
   - 目标是只保留被明确允许的旧资源过渡逻辑。
5. 运行验证。
   - `npm run type-check`
   - `npm run dev:mp-weixin`

### 阶段 2：按设计稿补全页面

用户会提供页面设计稿图片。可以基于图片识别页面结构、组件层级、间距、颜色、字体大小倾向和交互状态，并实现 UniApp/Vue 页面布局。

建议页面顺序：

1. 首页：完成度较高，优先做 API 迁移后的 UI 细节对齐。
2. 成绩查询页：完成度较高，重点稳定加载态、空状态、错误态。
3. 课表页：核心复杂页面，建议单独处理周视图、课程块、详情弹层、切换周/学期。
4. 查课页和课程详情页：先搜索页，再详情页。
5. 考试、图书馆、生活、常用信息：按发布范围决定完成度。

用户发设计稿时，最好同时说明：

- 页面名称。
- 是否需要完全还原。
- 哪些按钮需要可点击。
- 哪些数据来自 API。
- 哪些数据可以先 mock。
- 是否需要空状态、加载状态、错误状态。

### 阶段 3：Models 解耦

当前 `src/models/` 同时承担 API 请求、本地缓存、字段转换和业务聚合。等 API 和主要页面稳定后，再做解耦，降低重构风险。

建议目标结构：

```text
src/services/       # 只负责 API 请求
src/models/         # 负责状态、缓存、业务聚合
src/adapters/       # 可选，负责后端字段 -> 前端字段转换
```

例如成绩模块可演进为：

```text
src/services/gradeService.ts
src/models/GradeModel.ts
```

`gradeService.ts` 只负责：

```text
fetchScore()
fetchGpaRanking()
```

`GradeModel.ts` 继续负责：

```text
get()
update()
load()
save()
```

页面仍优先依赖 `models`，不要直接散落调用 service。
